PermissionRules.swift」，generator 仿 DDDKit 掛進 `swift build`。

確認的 A：
- 格式 = **YAML**；SSOT 模型 = **獨立文件為唯一來源**。
- 驗收 = 從 YAML 經 build plugin 產出兩檔，與 **OC 現有 153 條語意等價**（permission 全集一致、rule 的

## 2026-06-10 — Schema 切換到 Option B（permissions/rules 兩段，徹底解耦）
起因：OC 團隊評估 schema 時提出真實 gap——`PermissionRule.requires` 是 `[String]`（AND 多權限），但
fused「1 entry = 1 perm = 1 rule」表達不出「一 endpoint 多權限」「多 endpoint 共用一權限」。user 選 B。
- 新 schema：`permissions:`（catalog：`{slot, operationId, description?}`）+ `rules:`
  （`{method, path, requires:[<slot>.<operationId> 參照], description?}`）。rule↔perm 多對多。
- 變更：PermissionDocument（拆 `PermissionCatalogEntry` + `RuleEntry`）、PermissionEmitter（從兩段渲染、
  ref 解析、dangling-ref 驗證）、`scripts/oc_to_yaml.py`（產 split fixture）、fixtures、IAMContext.permissions.yaml、
  PermissionKitExample yaml、ParityTests（ruleTuples 支援多 requires）+ 新增 B 能力測試。
- parity 不破：OC 1:1 轉成 153 catalog + 153 rules（每條 requires 自己那條）→ 產出與 snapshot 語意相同。
